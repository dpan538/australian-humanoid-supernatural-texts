# Data And Methods Draft

## 3 Data And Methods

This study uses the Australian Public Text Archive of Supernatural Humanoid Narratives and Encounters as a methodological case study in provenance-aware public-text archiving. The archive is designed for the analysis of public representation, mediation, terminology, source circulation, and archival visibility. It is not designed to adjudicate supernatural claims or to transform public narratives into assertions about occurrence. This distinction is not merely rhetorical. It determines the archive's unit of analysis, source policy, data model, map policy, and treatment of candidate leads. The central methodological premise is that discovery is not evidence: the fact that a public web page, catalogue entry, search result, aggregator page, or access platform exposes a trace does not mean that the trace satisfies the archive's criteria for a source-grounded narrative unit. `[CITE: digital humanities archives]` `[CITE: archival provenance]`

The paper corpus was frozen through the paper-preparation workflow configured in `config/paper_hss_freeze.yaml`. The freeze identifier is `paper_hss_discovery_not_evidence_20260706`, generated from the local repository state recorded in `docs/paper/hss_discovery_not_evidence/CORPUS_SNAPSHOT.md`. The freeze manifest records the active SQLite database path, frontend exports, V2 exports, source-chain audits, canonical count reconciliation files, lead-mode outputs, strict closeout files, timestamps, checksums, and the git commit hash for the local state. It does not copy the SQLite database, raw source text, HTML, XML, PDFs, Word documents, cookies, credentials, or other restricted material into the paper release. The paper release directory contains aggregate CSV and JSON files, generated Markdown summaries, simple SVG figure renderings, and a redacted manual-audit sample. Counts reported in the manuscript are taken from `data/releases/paper_hss_discovery_not_evidence_20260706/paper_stats.json`, `paper_counts.csv`, and the derived tables under the same release directory. The live public website is not treated as the paper corpus unless a separate live capture is explicitly generated.

The freeze also imposes a count-family discipline. The archive contains several legitimate but non-equivalent populations: local frontend records, public map points, map flags, legacy flat records, V2 source items, V2 narrative units, internal narrative-location rows, strict-gate experiment rows, target-gap leads, source-chain audit rows, and release-overlay rows. These populations are intentionally not collapsed into a single corpus total. The paper therefore reports each count with its unit and provenance file. Live website display counts are treated as unavailable in the local paper freeze, even when local static frontend counts exist, because a deployed interface can diverge from a local export through release timing, cache state, or publication workflow. This rule prevents a common archival problem: a convenient public number becomes a manuscript fact without a reproducible source. It also allows the results section to treat count disagreement as a methodological finding rather than an error to be hidden. Differences among legacy records, normalized narrative units, source items, and mapped public display rows reveal how the archive's public, internal, review, and experiment layers organize different kinds of evidence.

The top-level unit of analysis is the source-grounded narrative unit. In V2 documentation, `narrative_unit` is the normalized object that replaces a looser flat-record interpretation of the legacy archive. A source-grounded narrative unit may describe an encounter account, apparition account, rumour, local legend, traditional narrative, spirit-person narrative, later retelling, descriptive belief record, heritage discourse, tourism discourse, catalogue pointer, or other public-text form, subject to the archive's scope and ethics rules. An encounter event is an optional subtype rather than the universal object. This design prevents the database from implying that all public-text traces are equivalent event reports. It also enables the archive to distinguish textual representation, publication history, place reference, source mediation, cultural sensitivity, and display status. `[CITE: folklore/vernacular belief]`

The source-chain model distinguishes four layers: `discovery_source`, `access_source`, `original_source`, and `evidence_source`. A `discovery_source` is the route through which a candidate trace becomes visible to the research workflow, such as a search result, public index, route registry, sitemap, aggregator, or catalogue query. A discovery source can be useful without being sufficient. An `access_source` is the platform through which material or metadata can be accessed, such as a public repository, digitization platform, catalogue interface, library system, or archived page. Access is a custody or delivery relation, not necessarily authorship. An `original_source` is the publication, organization, authorial context, collection, or originating public text to which the trace should be attributed when identifiable. An `evidence_source` is the specific source item or metadata record considered adequate to support a source-grounded narrative unit under the archive's record gates. The model therefore separates route discovery, access mediation, origin, and evidentiary adequacy. A single URL can sometimes occupy more than one layer, but the workflow does not assume that automatically.

The lead/record distinction operationalizes the source-chain model. A record is a source-grounded narrative unit or source item that satisfies the relevant provenance, publicness, source, date, place, ethics, and display gates for the archive layer in which it appears. A candidate lead is a reviewable public-text trace that has not met those gates or has been intentionally held because it lacks one or more required properties. A lead is not a failed record. It preserves archival visibility, identifies possible future review work, and documents why a trace cannot yet support public-record status. Lead mode is especially important for public-text archives because discovery routes often surface metadata-only traces, access-platform records, derivative web summaries, robots-constrained pages, or culturally sensitive items that should not be flattened into public records.

The strict record-gate experiment tested whether no-credential public surfaces could produce target-gap records under strict constraints. The active configuration disallowed API keys, login, paywall bypassing, credentialed access, unsafe robots assumptions, and human row review. A strict target-gap record required the conjunction of date signal, controlled term signal, item-level URL or equivalent item identity, safe source chain, source quality, rights/publicness suitability, and no duplicate/noise/sensitivity blocker. This gate should be understood as an experiment in evidentiary sufficiency, not as a measure of how much public-text material exists. The paper reports the generated strict-gate counts as a method result and distinguishes them from frontend public-record counts, V2 normalized counts, and lead counts.

The lead-mode conversion experiment was the non-destructive response to strict-gate failure. Rather than weakening the record definition, the workflow converted traces that lacked one or more strict-gate requirements into target-gap leads. These leads were scored, bucketed, clustered, deduplicated, and assigned blockers or recommended next actions. The conversion preserved discovery evidence as reviewable metadata without promoting it into public records or map flags. This design makes absence under a strict gate analytically useful: it reveals where public archives fail to supply dates, item-level URLs, controlled terms, source-chain clarity, rights clarity, or ethics clearance in machine-readable form.

Blockers were classified from the generated `target_gap_leads` table. The blocker taxonomy includes missing date, missing item URL, missing term, strict record gate not met, ethics sensitive, and robots unknown in the current paper stats. These blocker categories are not value judgments about the source material. They identify the part of the provenance gate that prevents a candidate lead from becoming a record in the configured workflow. For example, a missing date can prevent temporal placement even when a route is otherwise promising; a missing item URL can indicate that a directory or catalogue page is visible but not sufficient as item-level evidence; a robots-unknown blocker prevents automated enrichment where permissions are unclear; and ethics-sensitive blockers hold material for culturally cautious review.

Source-family classification records how source material clusters by route family, organization, source type, or normalized public-map source family. It is used to detect concentration, not to rank cultural importance. Source families include archival catalogues, state libraries, museum and heritage pages, local history serials, repository full text, public-domain ebooks, broadcast catalogues, structured endpoints, and family labels used in frontend source-concentration audits. The paper reports both source organization/type counts and source-family concentration. It also reports missingness where source-family fields are absent, because an incomplete field cannot support a complete ranking. Source-family concentration is treated as an epistemic and infrastructural risk: a map or corpus can appear large while being shaped by a small number of mediating source families. The analysis therefore asks which infrastructures make public-text traces visible, not which narrative traditions are more important, more numerous, or more evidentially persuasive.

Map eligibility follows the repository's public map policy. A public map flag is a display location for a public record, not a claim about truth, habitat, population, or occurrence. One public record can produce zero or one public map flag. Eligible map flags require source-stated place evidence, coordinate evidence, verification status, an Australian jurisdiction, and a public record that is not suppressed, restricted, rejected, or scope-excluded. Publication locations, archive custody locations, source institution addresses, author residences, inferred state-only locations, and broad cultural regions without display clearance are not valid public map flags. The map policy therefore converts place references into controlled display decisions. It also protects culturally sensitive, broad, or ambiguous records by allowing them to remain summary-only, metadata-only, or unmapped.

Manual audit sampling was prepared to evaluate lead-to-record decisions without exposing raw text. The sample size was configured as 100 leads or fewer if fewer leads were available, with deterministic random seed 538. Sampling was stratified by `constraint_blocker` and `source_family` where those fields existed. Sensitive-looking rows were excluded from the public sample by default. The output includes metadata fields such as lead type, blocker, source family, route family, priority bucket, score, source name, source tier, target state, inferred year, signal-presence indicators, URL domain, duplicate status, sample stratum, and blank human coding columns. The coding columns are `source_chain_complete`, `original_source_identifiable`, `evidence_source_adequate`, `date_available`, `term_available`, `source_stated_place_available`, `ethics_sensitive`, `record_eligible`, `map_eligible`, `reason_not_eligible`, and `reviewer_notes`. The sample intentionally omits snippets, descriptions, summaries, raw metadata JSON, source-chain JSON, raw text paths, and full URLs.

Data safety and culturally sensitive material handling follow the repository ethics policy. Public discoverability is not treated as unrestricted permission. Public catalogue metadata is not treated as permission to extract restricted cultural knowledge. Aboriginal and Torres Strait Islander-related material requires attention to source/community terminology, cultural sensitivity, ethics review status, display mode, publicness, reuse assessment, and correction or takedown pathways where relevant. Restricted, secret or sacred, unpublished, community-controlled non-public, private, or access-controlled material is outside the public paper release. Sensitive public material may be withheld, retained as summary-only or metadata-only, or excluded from public display. The paper release reports aggregate statistics and redacted sample metadata only.

The reproducibility environment is intentionally lightweight. The repository uses Python scripts against `data/processed/australian_humanoid_figures.sqlite`, V2 CSV exports, and static frontend JSON exports. Paper outputs are generated through `make paper-freeze`, `make paper-stats`, `make paper-figures`, `make paper-audit-sample`, and `make paper-check`. The paper validation script scans generated outputs for secret-like strings, forbidden copied file types, sensitive-looking public sample rows, and count drift between generated Markdown and JSON/CSV statistics. The software environment also includes the Next.js frontend, but the article's descriptive statistics are generated from the paper freeze rather than from runtime interface claims. All count families are kept separate: live website display counts, local frontend export counts, legacy flat-record counts, V2 normalized counts, strict-gate experiment counts, lead-mode counts, priority lead counts, mapped public-record counts, source organization/source type counts, source-family concentration counts, blocker counts, and missingness counts.
